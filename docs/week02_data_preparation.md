# ChargeUp — SLM Week 2: Palo Alto Data Preparation

Week 2 now uses `src/palo_alto_data.py` as the canonical ingestion/cleaning pipeline for the instructor-linked City of Palo Alto ChargePoint dataset.

## Week 2 flow

1. Download `ChargePoint Data CY20Q4.csv` from the current City dataset endpoint; fall back to a public research mirror of the same file if the historical portal redirect fails.
2. Validate the real source schema before processing.
3. Parse `Start Date`, `End Date`, charging duration and total duration.
4. Convert energy, fee and geographic fields to numeric values.
5. Remove rows that cannot be used safely (invalid station/timestamp/geography/negative energy).
6. Derive per-session charging power only when charging duration is positive.
7. Aggregate real sessions to **station-hour** observations.
8. Build next-exact-hour demand and next-hour server-termination proxy targets by matching the timestamp exactly one hour ahead.
9. Keep current/future server-termination audit columns out of all supervised feature lists.
10. Save the cleaned full table, a small committed sample and a data-quality report.

## Source-derived hourly features

- latitude / longitude
- session count
- average charging minutes
- average total plugged-in duration
- average session power
- energy delivered
- fee total
- Level 1 / Level 2 / DC fast session shares

## Missing-value policy

The pipeline does not invent absent weather or hardware telemetry. Missing duration/power aggregates are repaired first with station medians, then a global median only for those source-derived numeric fields.

## Outlier policy

Impossible values such as negative energy/duration are rejected. Calculated power outside 0–500 kW is treated as missing. Statistical outliers are not globally clipped before the temporal train/test split; later model selection must learn any statistical transform only from training data.

## Leakage-safe target rule

For station-hour `t`, features contain only values from `t` plus calendar/geography data. Targets come from exactly `t + 1 hour` at the same station. If no record exists at `t + 1 hour`, next-hour demand and the server-termination proxy are both zero.

The source `Ended By` field is used only to construct the future proxy label and is not a model feature.

- `data/processed/palo_alto_hourly_sample.csv` — small real-data sample
